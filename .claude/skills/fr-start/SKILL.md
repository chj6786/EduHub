# 요구사항 착수: $ARGUMENTS

이 스킬은 **분석·설계·계획만** 한다. 파일을 만들거나 고치지 않는다. 구현은 사용자가 계획을 승인한 뒤에 시작한다.

## 1. 분석

- `docs/requirements.md`에서 해당 요구사항을 찾아 다음을 읽는다:
  - 요구사항 행
  - 관련 NFR
  - "결정 사항"(D-xx)
- 관련 코드를 읽는다. 대상은 도메인 패키지, 기존 엔티티, Flyway 마이그레이션, 컨트롤러 패턴이다.
- 요구사항이 애매한 부분은 질문으로 정리한다. 최대 5개까지만 적는다.

## 2. 설계 명세

아래 항목을 표나 목록으로 쓴다.

- **범위**: 이번에 하는 것과 하지 않는 것
- **API**: 메서드, 경로, 요청·응답 DTO, 상태 코드(400, 404, 409 등)
- **데이터**: 테이블과 컬럼 변경, 제약(유니크, 부분 인덱스), 다음 마이그레이션 번호 `V{n}`
- **트랜잭션과 동시성**:
  - 트랜잭션 경계
  - 락 대상과 순서
  - NFR-01에 해당하는지
- **보안**: 인증과 본인 확인이 필요한 곳(NFR-03). 아직 없으면 `TODO(NFR-03)`으로 표시한다.
- **테스트 시나리오**:
  - 단위 테스트
  - 슬라이스 테스트
  - 동시성 테스트(해당 시)

## 3. 구현 계획

- 작업을 T1, T2, …로 나눈다. 각 작업은 한 번 리뷰할 수 있는 크기로 한다.
- 작업마다 다음을 적는다:
  - 바꿀 파일
  - 완료 기준
  - 확인 명령(예: `./gradlew test --tests "*XxxTest*"`)
- 순서 의존이 있으면 표시한다.

## 4. 마무리

설계 명세와 계획을 보여 주고, 승인을 요청하며 멈춘다.
